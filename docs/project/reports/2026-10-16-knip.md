## Analysis boundaries and official guidance

Configuration follows the current official [installation guide](https://knip.dev/overview/getting-started), [Next.js plugin reference](https://knip.dev/reference/plugins/next), and [configuration reference](https://knip.dev/reference/configuration).

- `knip.jsonc` enables Next.js without replacing its built-in entry patterns. Routes, API handlers, metadata, instrumentation and Next configuration remain reachable even when a UI does not call them.
- Eleven classic JavaScript files and six CSS files are explicit entries because `index.html` loads them with script and stylesheet tags. The explicit list matches the HTML; it does not blanket-exempt every root file. HTML, CDN-loaded Chart.js/Supabase, static assets, SQL migrations and deployment archives remain preserved. Knip is not a browser-global, HTML event-handler or unused CSS-selector audit.
- The project glob covers JavaScript, TypeScript and CSS, excluding generated Next output, dependencies, coverage and `next-env.d.ts`. Including CSS allows discovery of the `tailwindcss` import in `app/globals.css` and reports orphaned module CSS alongside its component.
- Tests are explicit entries under `components` and `lib`. The installed Vitest configuration has only a resolve alias, with no `test` object; initial Knip analysis missed all 21 test files. Explicit patterns match the actual test suite and prevent false unused test-library findings. Next/TypeScript aliases and other enabled tool plugins remain active.
- The sole dependency exception is `server-only`. Installed Next.js documentation (`node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md`, “Preventing environment poisoning”) states Next resolves these imports internally and npm installation is optional. The exception avoids eight false unlisted-dependency findings without touching the server/client guards.
- No feature flag was enabled. Supabase, Plaid, Stripe, Resend, Finnhub, Sentry, PostHog, billing, email, campus and account code remain available for later integration work. No broad integration ignore was added.

Initial discovery also falsely reported the legacy CSS and test dependencies. Those were corrected through entry/project configuration, not deletion. Tailwind and both testing libraries are used. No package qualified for removal after configuration.
